# PRD — 감정 기반 문장 추천 웹사이트

**Version:** 1.0  
**Status:** 개발용 초안  
**Platform:** Responsive Web (Mobile First)  
**Languages:** Korean / English  
**Primary Users:** 일반 방문자, 관리자

---

# 1. 프로젝트 개요

## 1.1 서비스 정의

사용자가 현재 느끼는 감정을 선택하면, 해당 감정에 적합한 문장을 추천하는 웹사이트.

문장은 관리자가 책, 영상 등에서 수집한 콘텐츠를 기반으로 제공한다.

서비스의 목적은 단순히 명언을 무작위로 보여주는 것이 아니라, **사용자의 현재 심리 상태와 관련성이 높은 문장을 발견하고 읽도록 돕는 것**이다.

## 1.2 핵심 사용자 경험

1. 사용자가 웹사이트에 방문한다.
2. 현재 느끼는 감정을 하나 이상 선택한다.
3. 선택한 감정과 관련성이 높은 문장을 추천받는다.
4. 세로 스크롤을 통해 한 문장씩 읽는다.
5. 원하는 경우 감정을 변경하거나 전체 문장 목록을 확인한다.
6. 마음에 드는 문장은 고유 링크를 복사하여 공유한다.

감정을 선택하지 않고 랜덤 문장을 탐색하는 기능도 제공한다.

## 1.3 핵심 설계 원칙

- 문장을 읽는 경험에 집중한다.
- 감정 선택 과정은 단순하고 직관적이어야 한다.
- 사용자는 Limbic Map의 이론을 몰라도 서비스를 이용할 수 있어야 한다.
- 사용자에게 AI 생성 문장을 제공하지 않는다.
- 추천은 관리자가 지정한 감정 태그를 기반으로 한다.
- 일반 사용자에게 회원가입을 요구하지 않는다.
- 모바일 사용성을 우선한다.

## 1.4 범위

### 포함 (In Scope)

- 감정 다중 선택
- 감정 태그 기반 문장 추천
- 관련 감정 기반 대체 추천
- 랜덤 문장 탐색
- 세로 스크롤 문장 뷰어
- 전체 문장 목록
- 추천 화면에서 감정 변경
- 문장 고유 URL 및 링크 복사
- 한국어/영어 인터페이스
- 관리자 인증
- 문장 CRUD
- 감정 태그 CRUD
- Big 3 분류 관리
- CSV/XLSX 일괄 등록
- 관리자 통계

### 제외 (Out of Scope)

- 일반 사용자 회원가입 및 로그인
- 일반 사용자 콘텐츠 등록
- 북마크 및 개인 저장 목록
- AI 문장 생성 및 AI 자동 분류
- AI 자동 번역
- 사용자 댓글 및 좋아요
- 문장 이미지 다운로드
- 감정 조합 통계
- 방문자 분석 대시보드
- Notion 연동 및 데이터 동기화

# 3. 감정 분류 시스템

## 3.1 분류 기준

감정 분류 체계는 Limbic Map의 Big 3를 기반으로 한다.

| Big 3 | 주요 개념 |
|---|---|
| Balance | 안정, 안전, 조화 |
| Dominance | 성취, 통제, 자율 |
| Stimulance | 자극, 탐험, 변화 |

Big 3는 감정 자체의 명칭이 아니라 감정 및 동기와 관련된 상위 분류 체계로 활용한다.

사용자에게는 Big 3를 노출하지 않는다.

## 3.2 감정 태그 구조

관리자는 Big 3에 연결되는 하위 감정 태그를 생성한다.

예시:

- 조급함
- 불안감
- 두려움
- 외로움
- 좌절감
- 무기력함
- 부담감

위 목록은 예시이며 최종 감정 목록은 기존 CSV 데이터 및 관리자 설정을 기준으로 한다.

## 3.3 Big 3와 감정의 관계

하나의 감정 태그는 여러 Big 3 영역에 연결될 수 있다.

예시:

`조급함 → Dominance + Balance`

데이터 관계:

- Big 3 : Emotion Tag = 다대다(N:M)
- Emotion Tag : Quote = 다대다(N:M)

Big 3 영역의 연결은 관리자가 직접 지정한다.

AI 또는 키워드 추론으로 연결 관계를 자동 확정하지 않는다.

## 3.4 감정 태그 관리 규칙

- 감정 태그 이름은 한국어와 영어를 별도로 관리한다.
- 동일한 감정 태그를 여러 문장에 연결할 수 있다.
- 감정 태그를 수정하면 연결된 문장에도 변경 사항이 반영된다.
- 감정 태그를 삭제하기 전 연결된 문장 수를 표시한다.
- 삭제 시 관련 문장과의 연결도 정리한다.
- 삭제로 인해 문장의 감정 태그가 0개가 되는 경우 삭제를 차단하거나 재지정을 요구한다.
- 감정 태그 이름의 중복 등록을 방지한다.
- 공개 여부를 별도로 관리할 수 있도록 설계한다.

# 4. 사용자 화면 및 기능 요구사항

## 4.1 화면 구성

| 화면 ID | 화면명 | 주요 기능 |
|---|---|---|
| U-01 | 홈 | 감정 선택, 랜덤 문장 보기 |
| U-02 | 문장 뷰어 | 추천 문장 세로 스크롤 |
| U-03 | 전체 문장 목록 | 추천 문장 전체 탐색 |
| U-04 | 감정 변경 패널 | 감정 추가·해제 |
| U-05 | 문장 상세 | 고유 URL로 문장 표시 |

## 4.2 U-01. 홈 화면

### 목적

사용자가 현재 감정을 선택하거나 랜덤 문장을 탐색하도록 한다.

### UI 요소

- 서비스 로고 또는 이름
- 언어 변경 메뉴 (KO / EN)
- 안내 문구: "지금 어떤 감정을 느끼고 있나요?"
- 감정 선택 태그
- 선택한 감정 수
- 문장 추천 보기 버튼
- 랜덤 문장 보기 버튼

### 동작

1. 감정 태그는 다중 선택할 수 있다.
2. 선택한 태그를 다시 누르면 선택이 해제된다.
3. 감정 태그를 하나 이상 선택하면 추천 버튼이 활성화된다.
4. 추천 버튼을 누르면 U-02로 이동한다.
5. 랜덤 문장 보기 버튼은 감정 선택 여부와 관계없이 동작한다.

### 감정 태그 정렬

전체 사용자가 많이 선택한 감정 순으로 정렬한다.

정렬 기준:

1. 감정 선택 횟수 내림차순
2. 동률이면 현재 인터페이스 언어 기준 이름순
3. 선택 통계가 없으면 이름순

선택 횟수는 서버에 익명 집계한다.

한 번의 추천 요청에서 선택한 감정 태그당 1회씩 집계하며, 태그를 단순히 선택·해제하는 과정은 집계하지 않는다.

동일한 추천 요청의 중복 전송은 중복 집계하지 않는다.

## 4.3 U-02. 문장 뷰어

### 목적

한 화면에 한 문장을 중심으로 표시하여 읽기에 집중하도록 한다.

### UI 요소

- 현재 선택한 감정 태그
- 감정 변경 버튼
- 전체 목록 보기 버튼
- 문장 원문
- 한국어 또는 영어 번역
- 저자 및 출처
- 출처 URL (등록된 경우)
- 링크 복사 버튼
- 현재 문장 위치 표시 (예: 3 / 24)

### 화면 동작

- 기본 탐색은 세로 스크롤 방식이다.
- 모바일에서는 터치 스크롤을 지원한다.
- PC에서는 마우스 휠, 트랙패드, 키보드 스크롤을 지원한다.
- 한 문장을 중심으로 화면을 구성한다.
- 다음 문장으로 자연스럽게 이동한다.
- 사용자가 위로 스크롤하면 이전 문장을 다시 볼 수 있다.
- 현재 추천 목록은 탐색 도중 순서가 바뀌지 않는다.

### 긴 문장 처리

문장 길이가 화면 높이를 초과할 수 있다.

이 경우 문장을 잘라내거나 말줄임표로 숨기지 않는다.

긴 문장은 내부 콘텐츠를 끝까지 읽을 수 있도록 자연스러운 스크롤을 허용한다.

문장 단위 스크롤 스냅은 짧은 문장에서만 적용하거나, 긴 문장 읽기를 방해하지 않는 방식으로 구현한다.

### 추천 목록 반복

추천 목록의 모든 문장을 확인하면 새로운 추천 순서를 생성한다.

- 감정 태그 일치 개수에 따른 우선순위 유지
- 동일 우선순위 내 무작위 재정렬
- 가능한 경우 직전 마지막 문장과 다음 첫 문장의 중복 방지
- 문장이 1개뿐이면 중복 허용

반복 경계에서는 새 추천 목록이 시작됨을 간단히 안내할 수 있다.

## 4.4 U-03. 전체 문장 목록

### 목적

현재 추천된 문장을 한 화면에서 목록으로 탐색하도록 한다.

### 기능

- 현재 추천 목록의 모든 문장을 표시
- 추천 우선순위와 정렬 순서 유지
- 원문, 번역, 출처 표시
- 문장 선택 시 해당 문장의 상세 또는 뷰어 위치로 이동
- 문장별 링크 복사 지원
- 목록에서 뷰어로 복귀 가능

문장 개수가 많아질 경우 성능을 고려해 페이지 단위 로딩 또는 가상 스크롤을 적용한다.

## 4.5 U-04. 감정 변경 패널

### 목적

추천 화면을 벗어나지 않고 선택한 감정을 변경한다.

### 동작

1. 감정 변경 버튼 클릭
2. 패널 표시
3. 기존 선택 감정 유지
4. 감정 추가 또는 해제
5. 적용 버튼 클릭
6. 추천 목록 재생성
7. 첫 번째 문장부터 표시

변경을 취소하면 기존 추천 목록과 현재 탐색 위치를 유지한다.

모든 감정을 해제한 경우 적용 버튼을 비활성화한다.

모바일에서는 바텀시트, PC에서는 적절한 다이얼로그 또는 패널 형태를 사용한다.

## 4.6 U-05. 문장 상세 및 공유

각 문장은 고유한 URL을 가진다.

예시:

`/quotes/{quoteId}`

### 요구사항

- 링크를 열면 해당 문장을 직접 표시한다.
- 로그인 없이 접근 가능하다.
- 원문, 번역, 출처를 표시한다.
- 문장을 수정해도 기존 URL은 유지된다.
- 삭제되었거나 비공개인 문장은 적절한 안내 화면을 표시한다.
- 링크 복사 버튼 클릭 시 클립보드에 URL을 복사한다.
- 복사 성공 및 실패에 대한 피드백을 제공한다.

공유 링크의 미리보기 제목 및 설명은 공개 가능한 콘텐츠 범위 내에서 구성한다.

# 5. 문장 추천 알고리즘

## 5.1 기본 원칙

추천 알고리즘은 AI를 사용하지 않는다.

관리자가 문장에 직접 연결한 감정 태그를 기준으로 추천한다.

## 5.2 직접 일치 추천

사용자가 선택한 감정 집합을 S, 문장에 연결된 감정 집합을 Q라고 정의한다.

일치 점수:

`matchScore = |S ∩ Q|`

예시:

사용자 선택:

`조급함, 불안감, 외로움`

| 문장 | 연결 태그 | 점수 |
|---|---|---|
| A | 조급함, 불안감, 외로움 | 3 |
| B | 조급함, 불안감 | 2 |
| C | 외로움 | 1 |
| D | 무기력함 | 0 |

추천 대상은 matchScore가 1 이상인 공개 문장이다.

### 정렬

1. matchScore 내림차순
2. 동일 점수 그룹 내 무작위 정렬

예:

`A(3) → B(2) → C(1)`

점수가 0인 문장은 직접 추천 목록에서 제외한다.

## 5.3 직접 일치 결과가 없는 경우

선택한 감정에 연결된 문장이 하나도 없으면 Big 3를 이용해 대체 추천을 제공한다.

### 처리 순서

1. 사용자가 선택한 감정 태그를 조회한다.
2. 각 감정에 연결된 Big 3 영역을 수집한다.
3. 해당 영역에 속한 다른 감정 태그를 조회한다.
4. 이 태그들과 연결된 공개 문장을 검색한다.
5. 관련성이 높은 문장을 우선 정렬한다.

### 대체 추천 점수

후보 문장이 연결된 감정들의 Big 3 영역과 사용자 선택 감정의 Big 3 영역을 비교한다.

`fallbackScore = 공통 Big 3 영역 개수`

공통 영역 개수가 많은 문장을 먼저 추천하고, 동률은 무작위 정렬한다.

### 사용자 안내

대체 추천은 직접 일치 추천과 구분한다.

예시:

"선택한 감정에 정확히 일치하는 문장은 없지만, 관련된 감정의 문장을 추천해 드릴게요."

### 최종 결과 없음

관련 Big 3 영역에도 공개 문장이 없다면 결과 없음 화면을 표시한다.

- 다른 감정 선택 안내
- 감정 변경 버튼
- 랜덤 문장 보기 버튼

## 5.4 랜덤 문장 추천

감정 선택 없이 모든 공개 문장을 대상으로 무작위 순서를 생성한다.

- 비공개 문장은 제외
- 목록 내 중복 문장 제외
- 전체 탐색 후 새 순서 생성
- 가능한 경우 직전 문장 반복 방지

## 5.5 추천 세션

한 번 생성된 추천 목록은 해당 탐색 세션에서 순서를 유지한다.

다음 상황에서는 새 목록을 생성한다.

- 새로운 감정 선택 후 추천 요청
- 감정 변경 적용
- 추천 목록을 모두 탐색한 후 새 순서 요청
- 랜덤 문장 보기 새로 시작

추천 중인 목록의 문장 ID 및 순서를 상태로 관리하여 화면 전환 시 불필요하게 재정렬하지 않는다.

# 7. CSV/XLSX 데이터 가져오기

## 7.1 기존 데이터

관리자는 이미 CSV 파일로 문장을 보유하고 있다.

기존 CSV 열은 다음 세 가지다.

1. `문장 내용`
2. `림빅맵 중 어디에 해당하는지`
3. `구체적 키워드`

예시:

| 문장 내용 | 림빅맵 중 어디에 해당하는지 | 구체적 키워드 |
|---|---|---|
| Desire is the contract... | Dominance, Balance | 조급함, 불안감 |

기존 CSV 파일을 별도 수정하지 않고 가져올 수 있도록 구현한다.

## 7.2 복수 값 파싱

복수 값은 쉼표로 구분한다.

예:

`조급함, 불안감`

파싱 결과:

`["조급함", "불안감"]`

### 처리 규칙

1. 쉼표 기준 분리
2. 각 항목의 앞뒤 공백 제거
3. 빈 문자열 제거
4. 동일한 값 중복 제거
5. 서로 다른 태그명은 자동 병합하지 않음

예:

`조급함,  불안감, 조급함, `

결과:

`["조급함", "불안감"]`

공백 자체는 구분자가 아니다. `성과 압박`처럼 띄어쓰기가 포함된 태그는 하나의 태그로 유지한다.

CSV 파일의 쉼표는 정상적인 CSV 인용 규칙에 따라 파싱해야 한다. 단순 문자열 줄 분리로 CSV 전체를 해석해서는 안 된다.

## 7.3 필드 매핑

| CSV 열 | 대상 데이터 |
|---|---|
| 문장 내용 | Quote.originalText |
| 림빅맵 중 어디에 해당하는지 | 문장별 Big 3 분류 |
| 구체적 키워드 | EmotionTag 연결 |

원문 언어는 관리자 검토를 통해 확정한다.

번역, 저자, 출처명, URL은 CSV에 없으므로 빈 값으로 가져온다.

## 7.4 Big 3 데이터 보존

기존 CSV에는 문장별 Big 3 분류가 직접 기록되어 있다.

반면 웹사이트의 추천 구조에서는 감정 태그에 Big 3 영역이 연결된다.

두 정보가 충돌할 수 있으므로 다음 정책을 적용한다.

- 기존 CSV의 문장별 Big 3 값은 원본 메타데이터로 보존한다.
- 가져오기 과정에서 문장별 Big 3와 감정 태그의 Big 3 연결 관계를 비교한다.
- 불일치가 있으면 관리자에게 표시한다.
- 기존 데이터를 임의로 덮어쓰지 않는다.
- 실제 추천은 관리자가 확정한 감정 태그와 Big 3 연결 관계를 기준으로 한다.

이를 위해 Quote에 `importedBig3Ids`와 같은 원본 분류 보존 필드를 추가할 수 있다.

## 7.5 일괄 등록 과정

1. CSV 또는 XLSX 파일 선택
2. 파일 형식 및 인코딩 확인
3. 열 자동 인식
4. 열 매핑 미리보기
5. 복수 태그 파싱
6. 기존 감정 태그와 대조
7. 신규 감정 태그 후보 표시
8. 관리자 검토 및 연결 관계 확정
9. 중복·오류 검사
10. 최종 등록

## 7.6 검증

다음 항목을 확인한다.

- 빈 문장
- 중복 문장
- 존재하지 않는 Big 3 값
- 등록되지 않은 감정 태그
- 감정 태그가 없는 문장
- 잘못된 CSV 형식
- 잘못된 인코딩
- 비정상적으로 긴 콘텐츠
- 유효하지 않은 URL

검증 결과는 오류·경고·정상 항목으로 구분한다.

일부 행에 오류가 있어도 정상 행을 확인할 수 있어야 한다.

관리자는 오류를 수정하거나 해당 행을 제외하고 등록할 수 있다.

중복 검사는 원문 앞뒤 공백 및 연속 공백을 정규화한 값을 기준으로 수행한다. 기존 문장을 자동 덮어쓰지 않는다.

일괄 등록은 미리보기와 최종 확인을 분리하고, 중복 제출로 동일 데이터가 여러 번 등록되지 않도록 한다.

# 8. 관리자 페이지

## 8.1 화면 구성

| 화면 ID | 화면명 | 기능 |
|---|---|---|
| A-01 | 로그인 | 관리자 인증 |
| A-02 | 대시보드 | 통계 요약 |
| A-03 | 문장 목록 | 검색, 조회, 수정, 삭제 |
| A-04 | 문장 등록·편집 | 콘텐츠 입력 및 태그 연결 |
| A-05 | 일괄 등록 | CSV/XLSX 업로드 |
| A-06 | 감정 태그 관리 | 감정 CRUD 및 Big 3 연결 |
| A-07 | 통계 상세 | 감정 선택·문장 조회 통계 |

## 8.2 문장 관리

관리자는 다음 작업을 수행할 수 있다.

- 문장 신규 등록
- 기존 문장 수정
- 문장 삭제
- 문장 공개/비공개 전환
- 원문 및 번역 편집
- 출처 정보 편집
- 감정 태그 복수 지정
- 문장별 Big 3 원본 분류 확인
- 저작권 검토 상태 변경

문장 목록에서는 원문, 태그, 공개 상태를 기준으로 검색 및 필터링할 수 있어야 한다.

삭제는 확인 절차를 거치며, 삭제된 문장의 고유 URL은 재사용하지 않는다.

## 8.3 감정 태그 관리

- 태그 신규 생성
- 한국어/영어 이름 수정
- Big 3 복수 연결
- 태그 활성/비활성
- 태그 삭제
- 연결된 문장 수 확인

비활성 태그는 일반 사용자에게 표시하지 않는다.

비활성 태그가 기존 문장에 연결되어 있더라도 직접 추천 조건으로 사용하지 않는다.

## 8.4 관리자 통계

### 감정 선택 통계

- 감정별 누적 선택 횟수
- 가장 많이 선택된 감정 순위
- 전체 감정 선택 횟수

### 문장 조회 통계

- 문장별 누적 조회 횟수
- 가장 많이 조회된 문장 순위
- 전체 문장 조회 횟수

### 집계 정책

감정 선택은 추천 요청 확정 시 집계한다.

문장 조회는 해당 문장이 실제 화면에 표시되었을 때 집계한다.

동일한 문장을 화면에 계속 표시하거나 짧은 시간 동안 스크롤을 왕복하는 행동은 중복 조회로 과도하게 집계하지 않는다.

초기 구현 기준으로, 문장이 화면의 주요 영역에 1초 이상 노출되었을 때 조회 이벤트를 발생시키고 동일 탐색 세션 내 동일 문장은 1회만 집계한다.

통계는 개인 식별 없이 집계하며, 사용자별 감정 선택 기록을 저장하지 않는다.

# 9. 다국어 지원

## 9.1 지원 언어

- 한국어 (`ko`)
- 영어 (`en`)

## 9.2 번역 대상

- 내비게이션
- 버튼
- 안내 문구
- 감정 태그
- 오류 메시지
- 빈 상태 메시지
- 관리자 인터페이스의 사용자 표시 텍스트

관리자 인터페이스의 기본 언어는 한국어로 시작할 수 있다.

## 9.3 문장 표시 정책

문장 원문은 항상 원래 언어로 표시한다.

사용자가 한국어를 선택한 경우:

- 원문 표시
- 한국어 번역이 있으면 표시
- 없으면 번역 영역 생략

영어를 선택한 경우:

- 원문 표시
- 영어 번역이 있으면 표시
- 없으면 번역 영역 생략

원문과 번역이 동일하면 중복 표시하지 않는다.

AI 자동 번역은 사용하지 않는다.

## 9.4 언어 설정 유지

- 첫 방문 시 브라우저 언어를 참고해 기본 언어 설정
- 지원하지 않는 언어는 한국어 기본값
- 사용자가 직접 언어 변경 가능
- 선택한 언어는 브라우저 로컬 저장소에 유지
- 재방문 시 기존 설정 우선 적용

# 10. UI/UX 디자인 요구사항

## 10.1 디자인 방향

**Minimal Typography-focused Design**

문장을 중심으로 구성된 미니멀한 디자인.

### 원칙

- 넓은 여백
- 절제된 색상
- 명확한 정보 위계
- 높은 가독성
- 불필요한 장식 최소화
- 읽기 흐름을 방해하지 않는 인터랙션

## 10.2 정보 위계

1. 문장 원문
2. 번역
3. 저자 및 출처
4. 보조 기능

## 10.3 반응형

모바일 우선으로 설계한다.

### 모바일

- 감정 태그 터치 선택
- 세로 스크롤 기반 문장 탐색
- 충분한 터치 영역
- 작은 화면에서도 긴 문장 읽기 지원
- 감정 변경 바텀시트

### PC

- 본문 최대 너비 제한
- 넓은 여백 유지
- 마우스 휠 및 키보드 탐색
- 감정 변경 패널
- 과도하게 긴 텍스트 줄 방지

## 10.4 타이포그래피

구체적인 폰트는 디자인 단계에서 결정한다.

다음 기준을 만족해야 한다.

- 한글과 영문 모두 가독성이 높을 것
- 긴 문장에 적절한 행간 적용
- 반응형 글자 크기
- 접근 가능한 명암 대비
- 사용자의 브라우저 글자 크기 확대 지원

## 10.5 모션

문장 전환에는 절제된 움직임을 적용할 수 있다.

- 과도한 패럴랙스 금지
- 불필요한 자동 재생 애니메이션 금지
- `prefers-reduced-motion` 지원
- 동작 감소 설정 시 부드러운 스크롤·전환 효과 최소화

- 모바일 환경에서 빠른 초기 화면 표시
- 문장 데이터는 필요한 범위만 로딩
- 대량 문장 목록에 대한 페이지네이션 또는 가상화
- 이미지에 의존하지 않는 가벼운 UI
- 추천 목록 생성 시 불필요한 데이터베이스 요청 최소화

초기 성능 목표는 실제 데이터 규모와 배포 환경을 확인한 후 확정한다.

## 12.2 보안

- 관리자 인증 필수
- 관리자 API 권한 서버 검증
- 비공개 문장 접근 차단
- 입력 데이터 검증
- XSS 방지
- URL 안전성 검사
- 관리자 작업 오류 처리
- 통계 집계 API의 과도한 호출 제한
- 관리자 비밀번호 및 비밀 키를 클라이언트에 노출하지 않음

## 12.3 접근성

- 키보드만으로 주요 기능 사용 가능
- 감정 태그 선택 상태를 시각적·의미적으로 전달
- 적절한 명암 대비
- 스크린리더를 위한 버튼 레이블
- 포커스 표시
- 동작 감소 지원
- 긴 텍스트 확대 시 레이아웃 유지

## 12.4 개인정보

일반 사용자의 계정이나 개인 프로필을 생성하지 않는다.

감정 선택 통계와 문장 조회 통계는 익명 집계한다.

개인별 감정 기록이나 사용자 식별자를 영구 저장하지 않는다.

분석 및 통계 수집 방식에 따라 필요한 개인정보 안내와 관련 법적 요건을 확인한다.

## 12.5 저작권

문장은 책, 영상 등 외부 콘텐츠에서 수집될 수 있다.

따라서 출처 정보와 공개 가능 여부를 관리해야 한다.

- 저자 및 출처 정보 저장
- 출처 URL 저장
- 저작권 검토 상태 관리
- 공개 허용 여부 확인
- 검토되지 않은 콘텐츠는 기본적으로 비공개
- 출처 표기만으로 사용 허락이 확보된 것으로 간주하지 않음

# 13. 권장 기술 구조

구체적인 기술 스택은 개발 환경에 따라 조정 가능하다.

다만 다음 구조를 권장한다.

## 13.1 프런트엔드

- React
- TypeScript
- Vite
- 반응형 CSS
- 다국어 라이브러리 (예: i18next)

## 13.2 백엔드 및 데이터

- 인증 기능
- 문장 데이터 저장
- 감정 태그 관리
- 통계 집계
- CSV/XLSX 업로드 처리
- 관리자 전용 API

Firebase Authentication과 Firestore를 사용할 수 있다.

단, 해당 기술 사용은 필수 확정 사항이 아니다.

## 13.3 주요 데이터 관계

- Quote ↔ EmotionTag: N:M
- EmotionTag ↔ Big3: N:M
- EmotionTag → EmotionSelectionStat: 1:1
- Quote → QuoteViewStat: 1:1

구현 시 조회 효율을 위해 비정규화할 수 있지만, 데이터의 정합성을 유지해야 한다.

# 14. 테스트 및 인수 기준

## 14.1 감정 선택

- [ ] 감정을 하나 선택할 수 있다.
- [ ] 여러 감정을 동시에 선택할 수 있다.
- [ ] 선택한 감정을 해제할 수 있다.
- [ ] 감정 미선택 시 추천을 시작할 수 없다.
- [ ] 선택 횟수 기준으로 감정이 정렬된다.

## 14.2 추천 알고리즘

- [ ] 태그 일치 개수를 정확하게 계산한다.
- [ ] 일치 개수가 많은 문장을 우선 표시한다.
- [ ] 동일 점수 내 무작위 정렬이 작동한다.
- [ ] 추천 세션 중 순서가 유지된다.
- [ ] 직접 일치 결과가 없으면 Big 3 기반 추천을 실행한다.
- [ ] 대체 추천임을 사용자에게 알린다.
- [ ] 대체 추천도 없으면 결과 없음 화면을 표시한다.
- [ ] 비공개 문장은 추천하지 않는다.

## 14.3 문장 뷰어

- [ ] 세로 스크롤로 다음 문장을 볼 수 있다.
- [ ] 이전 문장으로 돌아갈 수 있다.
- [ ] 긴 문장이 잘리지 않는다.
- [ ] 원문, 번역, 출처를 올바르게 표시한다.
- [ ] 전체 목록으로 전환할 수 있다.
- [ ] 감정 변경 후 추천 목록이 갱신된다.
- [ ] 마지막 문장 이후 새로운 무작위 순서를 생성한다.

## 14.4 CSV/XLSX

- [ ] 기존 CSV의 3개 열을 인식한다.
- [ ] 쉼표로 복수 값을 분리한다.
- [ ] 쉼표 앞뒤 공백을 제거한다.
- [ ] 태그 내부 공백은 보존한다.
- [ ] 중복 태그를 제거한다.
- [ ] 미등록 태그를 검출한다.
- [ ] 기존 Big 3 정보를 보존한다.
- [ ] 중복 문장을 검출한다.
- [ ] 등록 전 미리보기를 제공한다.
- [ ] 오류가 있는 행을 구분한다.

## 14.5 관리자

- [ ] 관리자만 콘텐츠를 수정할 수 있다.
- [ ] 문장 CRUD가 정상 작동한다.
- [ ] 감정 태그 CRUD가 정상 작동한다.
- [ ] Big 3 복수 연결이 가능하다.
- [ ] 문장 공개 상태를 변경할 수 있다.
- [ ] 감정 선택 통계를 확인할 수 있다.
- [ ] 문장 조회 통계를 확인할 수 있다.

## 14.6 다국어 및 공유

- [ ] 한국어/영어 전환이 가능하다.
- [ ] 감정 태그 이름이 선택 언어에 맞게 표시된다.
- [ ] 번역이 없는 문장을 정상 표시한다.
- [ ] 언어 설정이 재방문 시 유지된다.
- [ ] 문장별 고유 URL이 작동한다.
- [ ] 공유 링크를 통해 해당 문장에 직접 접근할 수 있다.

# 16. 미확정 사항

다음 사항은 현재까지 사용자에게 확정받지 않은 항목이다.

| 항목 | 상태 |
|---|---|
| 서비스 이름 | 미정 |
| 로고 및 브랜드 아이덴티티 | 미정 |
| 정확한 폰트 및 색상 토큰 | 미정 |
| 실제 CSV 데이터의 전체 값과 표기 규칙 | 파일 확인 필요 |
| 감정 태그 초기 목록 | CSV 확인 후 확정 |
| Big 3 연결 관계의 최종 검수 | 관리자 확인 필요 |
| 배포 및 호스팅 플랫폼 | 미정 |
| 실제 사용할 데이터베이스 | 미정 |
| 관리자 인증 방식 | 미정 |
| 문장 저작권 공개 범위 | 검토 필요 |
| 통계 보존 기간 | 미정 |

미확정 사항은 구현에 필수적인 기술적 선택과 제품 정책을 구분하여 처리한다.

제품 정책에 영향을 주는 항목은 임의로 확정하지 않는다.

# 17. AI 개발 도구 실행 지침

이 PRD를 기반으로 웹사이트를 구현하는 AI 개발 도구는 다음 원칙을 따라야 한다.

1. PRD의 확정된 기능과 비즈니스 규칙을 임의로 변경하지 않는다.
2. 개발 시작 전 현재 프로젝트 구조와 기존 코드를 확인한다.
3. 기존 프로젝트가 있다면 기존 기술 스택과 디자인 시스템을 우선 검토한다.
4. 실제 CSV 파일을 확인하기 전까지 데이터 내용을 추측하지 않는다.
5. CSV의 원문, Big 3 분류, 감정 키워드를 임의로 수정하거나 재분류하지 않는다.
6. 관리자 인증과 데이터 접근 권한을 반드시 서버 측에서 검증한다.
7. 추천 알고리즘은 AI가 아닌 결정적 태그 점수 계산과 무작위 정렬을 사용한다.
8. 문장 추천 결과는 태그 일치 개수 우선순위를 유지한다.
9. 사용자의 감정 선택 데이터는 개인 식별 정보와 연결하지 않는다.
10. 정상 흐름뿐 아니라 오류, 예외, 빈 상태, 경계 조건을 구현한다.
11. 주요 기능에 대한 자동 테스트를 작성한다.
12. 구현 과정에서 PRD와 충돌하거나 불명확한 요구사항을 발견하면 임의로 결정하지 말고 사용자에게 확인한다.
